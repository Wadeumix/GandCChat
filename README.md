# G&C Chat

Gemini（ブラウザ上のAI）と Claude Code の会話を、話題ごとの「ルーム」に分けてチャット形式で蓄積するためのローカルWebアプリです。

## できること

- **ルーム（話題）を複数作成**し、話題ごとに会話を分離して管理
- 会話はSQLiteデータベース（`gcc_chat.db`）に永続化
- ルームごとに `logs/<slug>.md` へ**追記専用**でmdログも自動出力（人間が読む用・バックアップ用）
- Discord風サイドバー＋LINE風チャットバブルUIで閲覧
- Gemini・Claude それぞれの発言をブラウザから貼り付けて記録
- 「⬇ Geminiから取り込む」ボタンで、専用ChromeのGeminiタブから最新のAI発言を自動抽出して記録
- 重複（前回と同じ発言）・別セッション（前回と違うGemini会話）を検知して警告
- Claudeの発言に「📋 Gemini用にコピー」ボタン。ルームごとに初回だけ「GCC経由の会話です」という注釈を自動付与
- 「🔗 Claude Codeとリンク」ボタンで、ログファイルのパス入りプロンプトをコピー。どのClaude Codeセッションに貼り付けてもそのまま文脈を読める
- **リンク後は、導入前の会話インポートが完了するまで会話開始をロック**（①リンク→②インポート→③会話開始、のステップ表示付き）
- GCC導入前の会話は、**PDF（共有ページを印刷保存したもの）アップロード推奨**、またはテキスト全文貼り付けで一括インポート可能
- ネイティブウィンドウの`.app`としてビルド可能（`./build_app.sh`）。ターミナル常駐不要

## できないこと（意図的な制約）

- Gemini・claude.ai いずれのWebチャットへの**自動送信は行いません**。送信は常にユーザーが手動でコピー＆ペーストしてください
- Geminiからの取り込みも**ボタンを押した時だけ**（常時ポーリングはしない）
- Claudeの発言を自動生成する機能はありません。このアプリは記録・閲覧専用です。Claude Codeセッション側で発言内容を考え、テキストエリアに貼り付けて「ログに追加」してください

## 起動方法

```bash
python app.py
```

起動後、ブラウザで `http://127.0.0.1:5050` を開いてください。初回起動時は「雑談」ルームが自動で1つ作られます。

## デスクトップアプリとして使う（推奨）

ターミナル常駐やブラウザタブでの利用が煩わしければ、ネイティブウィンドウの`.app`としてビルドできます。URLバーの無い普通のMacアプリのウィンドウとして動きます。

### ビルド

```bash
./build_app.sh
```

`dist/GCC Chat.app` が生成されます。Applicationsフォルダに移動するか、Dockに登録して使ってください。

### 仕組み

- `desktop.py` がFlaskサーバーをバックグラウンドスレッドで起動し、[pywebview](https://pywebview.flowrl.com/)でネイティブウィンドウとして表示します
- Gemini取り込み用の専用Chromeは、アプリ化しても変わらず**別ウィンドウ**です（Googleログインの都合でGCCアプリ自体には埋め込めません）
- ビルドした`.app`を実行すると、データの保存先が自動的に`~/Library/Application Support/GCC Chat/`に切り替わります（`__file__`基準のパスは`.app`内では起動のたびに変わってしまうため）。ソースから`python app.py`で起動する開発時は、従来通りプロジェクト直下に保存されます

### 再ビルドが必要なタイミング

`app.py`やテンプレートを変更したら、`./build_app.sh`を再実行してください。ソースから直接`python app.py`で動かしている間は再ビルド不要です。

## データの保存先（パス）

| 実行方法 | デフォルトパス | 変更方法 |
|---|---|---|
| `python app.py`（開発時） | プロジェクト直下 `./gcc_chat.db` / `./logs/` | 環境変数 `GCC_DB_PATH` / `GCC_LOGS_DIR` |
| `GCC Chat.app`（ビルド後） | `~/Library/Application Support/GCC Chat/` | 同上（環境変数が優先される） |

保存先を変えたい場合は起動前に環境変数を設定してください。

```bash
export GCC_DB_PATH=~/Documents/gcc/gcc_chat.db
export GCC_LOGS_DIR=~/Documents/gcc/logs
python app.py
```

## 使い方

1. サイドバー下部の「新しい話題名」に入力して「＋」を押し、話題ごとのルームを作成する
2. 左のルーム一覧から話題を選んで会話画面を開く
3. Geminiのブラウザで返ってきた発言をコピーし、「Gemini の発言を貼り付け」を選んで貼り付け →「ログに追加」
4. Claude Code側でそのログを読み、次の発言を考える
5. 考えた発言を「Claude の発言を記録」を選んで貼り付け →「ログに追加」（画面上に吹き出しとして表示される）
6. 表示されたClaudeの発言をコピーし、Geminiのブラウザ画面に**手動で**貼り付けて送信する

この繰り返しで、ルームごとに会話が時系列で蓄積されていきます。

## Geminiからの自動取り込み（任意機能）

普段使いのChromeとは別の**専用Chromeプロファイル**を使い、Geminiの最新発言をボタン一つで取り込めます。

### セットアップ（初回のみ）

```bash
./launch_gemini_chrome.sh
```

これで`~/.gcc-chrome-profile`という専用プロファイルのChromeが、デバッグポート付き（`--remote-debugging-port=9222`）で起動します。開いたウィンドウでGoogleアカウントにログインしてください（普段使いのChromeのログイン状態には一切影響しません）。

### 使い方

1. GCC Chatの画面右上「⬇ Geminiから取り込む」を押す（専用Chromeが起動していなければ自動で起動する）
2. 最新のAI発言が自動でルームに記録される

### 注意点

- **常時監視はしません**。ボタンを押した瞬間の最新発言だけを取得します
- 同じ発言を連続で取り込もうとすると「すでに記録済みです」と警告されます
- 前回と異なるGemini会話（別のURL）から取り込もうとすると警告が出ます。意図した動作なら「それでも取り込む」を選んでください
- `--remote-debugging-port`は同一マシン上の他プロセスからも接続できてしまうため、**専用プロファイルを分離**することで普段使いのChromeへの影響を防いでいます
- 専用Chromeが閉じている場合は`launch_gemini_chrome.sh`が自動実行されます。手動で先に起動しておいても構いません

## Claude Codeとのリンク（導入前の会話インポート必須）

「🔗 Claude Codeとリンク」ボタンで、ログファイルの場所を伝えるだけでどのClaude Codeセッションとも文脈を共有できます。

### 使い方

1. ルーム画面右上の「🔗 Claude Codeとリンク」を押す → ログファイルの絶対パス入りプロンプトが自動でクリップボードにコピーされる
2. 貼り付けたいClaude Codeセッションのチャットに貼り付ける
3. **初回リンク時は、会話を始める前に「導入前の会話インポート」が必須になります**（①リンク→②インポート→③会話開始、の3ステップがヘッダー下に表示される）
   - 推奨: Geminiの共有ページ（画面右上の共有アイコン）を開き、ブラウザの「印刷 → PDFとして保存」でPDF化してアップロード
   - PDFはSPAのレンダリング崩れの影響を受けにくく、テキスト抽出が安定します
   - コピペのテキスト全文貼り付けにも対応
4. インポートが完了すると、通常の会話・「⬇ Geminiから取り込む」ボタンが使えるようになります

### リンク先のClaude Codeが応答を記録する方法

コピーされるプロンプトには、ログファイルのパスに加えて次のコマンドの案内が含まれています。

```bash
echo "応答本文" | python3 /path/to/GandCChat/gcc_post.py --room-id <id> --speaker Claude
```

**mdログファイルに直接書き込まない**でください（見出し形式を間違えると同期に失敗します）。このコマンドは`/rooms/<id>/add`と同じAPIを叩くので確実です。

なお、万一ログファイルに直接`## Claude（YYYY-MM-DD HH:MM）`形式で追記されてしまった場合でも、ページの表示・4秒間隔の軽量ポーリング時に自動でDBへ同期されるため、表示されないままにはなりません（フェイルセーフ）。

ブラウザの画面は4秒おきにメッセージ件数を確認し、増えていれば自動でリロードします。ページを開いたまま待っていれば、外部から投稿された内容も自動で反映されます。

### なぜ必須にしているか

Claude Codeとリンクする＝以後その会話はGCC経由で中継されることを意味するため、**リンクした時点までの文脈をお互いのAIが共有していないと話が噛み合わない**ためです。リンクせずにGCC単体で使う分には、このロックはかかりません。

## 他セッションへの受け渡し（メールボックス方式・上級者向け）

同一マシンでファイルパスを共有できない場合の代替手段です。通常は上記の「🔗 Claude Codeとリンク」で十分です。

「このルームのログを、どのClaude Codeセッションに渡すか」を、送信先を自由なラベル文字列で指定して受け渡せます。今この会話をしているセッションでも、別のターミナルで動いているCLIプロセスでも同じ仕組みで扱えます。

### 送る側（GCC Chat側）

1. ルーム画面右上の「📤 他セッションへ送る」を押す
2. 送信先ラベル（例:「このセッション」「trading-bot-cli」など好きな名前）を入力して送る
3. 内容は自動でそのルームの全ログになる

### 受け取る側

同じラベルを指定して、以下のどちらかで確認します。

```bash
python3 mailbox_check.py --target "trading-bot-cli"
```

または直接API:

```bash
curl "http://127.0.0.1:5050/handoffs?target=trading-bot-cli"
```

未読分だけが返り、取得後に既読にしたい場合は `--ack` オプション（APIなら`POST /handoffs/<id>/ack`）を使います。**常時ポーリングはしない**設計なので、必要な時に都度実行してください。「今の会話をしているセッション」宛てに送られたものは、そのセッション自身が同じAPIを叩けば確認できます。

## データ構造

```
rooms(id, name, slug, created_at, deleted_at, last_gemini_url, explainer_sent, link_requested, import_done)
messages(id, room_id, speaker, body, created_at, source_url, imported)
handoffs(id, room_id, target_label, content, created_at, consumed_at)
```

`messages.room_id` は `rooms.id` を参照し、ルーム削除時は関連メッセージも削除されます（`ON DELETE CASCADE`）。ただしルーム削除機能自体は現時点でUIに未実装です。

`logs/<slug>.md` は常に追記されるだけなので、過去のログを直接編集・削除しないでください（DBが正データ、mdは可読なコピー）。
